# Instance subscription evidence

```sh
jsn subscriptions evidence --limit 50 --json
jsn subscriptions evidence --limit 50 --get 'data.entitlements'
jsn subscriptions evidence --limit 50 --styled
```

Select the instance using normal explicit instance/profile/session resolution.
The command requires an instance; the existing offline `subscriptions schedules`
command and explicit `refresh` behavior are unchanged. `estimate ITOM` remains
an independent illustrative population comparison, not measured consumption.

## What this reports

The command reads sources visible to the account on the **queried instance**:

| Section | Candidate sources | Interpretation |
| --- | --- | --- |
| Entitlements | `license_details`, `subscription_entitlement` | Source observations; relationship, contractual authority and validity unverified |
| Allocation | `subscription_detail`, `account_subscription_entitlement`, `instance_subscription_entitlement` | Source observations, not role users or billable seats |
| Access | `sys_user_has_role` (not fetched) | Unavailable: existing SDK count/groupBy lacks a bounded distinct-user aggregate |
| Consumption | `itom_lu_ci_counts`, `usageanalytics_count`, `itom_lu_licensable_cis` | Source observations only, not guessed meters, deduplicated totals or a 90-day average |
| Installed hints | `sys_store_app`, `v_plugin`; existing App Client fallback when the Store table is forbidden | Separate Store installation and platform-plugin state observations |

Vendor instances may expose more evidence than other instances. No fixed schema,
commercial authority or equality of visibility is assumed. The table grouping is
a discovery aid, not proof that each row represents the category in a contract.

`subscription_detail` is filtered with `is_latest=true` only when that exact
non-reference boolean field is visible in its dictionary/inherited dictionary.
Otherwise observations are explicitly **not established as current/latest**.
No subscription-to-app relationship is inferred, and candidate mapping tables
remain outside this report until their references and meaning are verified.
Custom-table subscription mappings are not treated as a purchased-app catalog.

## Schema gate and projection

Strict SDK GET reads verify one visible `sys_db_object` definition and its parent
chain, and inspect bounded `sys_dictionary` rows. Missing definitions are
unavailable, not proof of a nonexistent table. Hidden parent/type/reference
metadata, cycles, ambiguous definitions, malformed envelopes and exceeded caps
prevent the affected source from being interpreted. The generic record-layout
reader's fallback hierarchy is deliberately not used as an existence check.

Subscription and consumption data is projected only through this vocabulary,
and only for a matching visible non-reference dictionary type:

- String/choice: `product_name`, `product_code`, `sku`, `license_type`,
  `subscription_type`, `unit`; string/choice/integer: `status`, `state`.
- Boolean: `active`, `is_latest`.
- Integer/longint/decimal/float/numeric: `quantity`, `purchased_quantity`,
  `allocated_quantity`, `allocated`, `used`, `consumption`, `count`, `ci_count`,
  `licensable_count`.
- Date/date-time: `sample_date`, `start_date`, `end_date`, `effective_date`,
  `sys_updated_on`.

These are allowed **field tokens**, not assumed schemas or verified meanings.
Other names/types remain unsupported even if a vendor instance exposes them.
References are exposed only as schema field/target metadata; reference values and
reference display values are omitted. Missing, invalid or redacted values are
`null`. No sums or arithmetic normalization are performed; numeric observations
remain their source strings (including a legitimately observed `"0"`).

The reused inventory readers use their existing product/version/activation and
installation-evidence contracts. Their Table API fields are restricted to visible
non-reference metadata; optional unknown fields are not requested. Internal IDs
used to validate inventory pages are not included in observations. Output contains
only product label/version, active state and Store installation evidence, not
customer accounts, usernames, CI identifiers or arbitrary raw rows.

Strings are bounded, reject email/URL/control-character/sys_id forms, and exclude
free-form descriptions and identity-bearing fields. This is a conservative field
projection, **not a general-purpose anonymizer**: a provider can put unexpected
content in an allowed product label. Review any real report before sharing it.
Provider exception text and arbitrary error codes are never included.

The fallback permits only the exact installed-tab discovery POST generated by the
single-page inventory reader: same instance origin, `/api/sn_appclient/appmanager/apps`,
`tab_context=installed`, `sysparm_limit=200`, `sysparm_offset=0`, and the literal
body `{}`. Other POSTs and Store install/update endpoints are rejected before SDK
transport. This exception bypasses only the SDK's GET-only `readOnly` method guard;
credential last-seen updates remain disabled. Ordinary evidence reads remain
GET-only Table/Stats requests to the queried instance.

## Bounds, coverage and freshness

- `--limit` defaults to 50; only integers 1–200 are accepted, before data I/O and
  before the handler requests an instance.
- Subscription/consumption sources each receive at most one ordered data request
  for `limit + 1` rows. One overflow row is discarded and marks truncation.
- Metadata: at most **96 SDK dispatches** per invocation, at most 16 ancestor
  definitions per source, at most 200 dictionary entries per ancestor plus one
  overflow probe. Repeated metadata lookups share invocation-local promises.
- Data/inventory: at most **16 SDK dispatches** in total. Reused inventories read
  at most one 200-row page each, plus their bounded before/after count requests;
  Store may use one installed-tab discovery fallback. `--limit` caps output rows,
  not that existing inventory reader's page size.
- Every API attempt receives a 10-second timeout. SDK session recovery retains its
  existing replay ceiling; `request_budget.http_attempt_ceiling` includes that
  multiplier. Authentication/session bootstrap/refresh requests are separate from
  the metadata/data API caps. No collector retry or persistent instance cache.

All sections disclose source, collection timestamp, freshness and coverage. A
visible `sys_updated_on` is per-row evidence, not proof of source-wide freshness.
Missing timestamps remain unknown. Provider-count completeness on an inventory
never becomes report-wide completeness or proof of ACL visibility/snapshot
consistency. Empty successful reads are `no-visible-rows`; missing/hidden,
forbidden, malformed and unsupported-schema sources remain unavailable, never
zero purchased rights or zero use. Authentication rejection is terminal and
sanitized rather than emitted as an apparently empty report.

## Not conclusions

Installed apps and active plugins are **hints and possibilities**, not contractual
rights, licensed/billable seats, production deployment or bills. A nonproduction
install does not prove a production install or bill. No environment type is
automatically detected. Allocation is not a valid unexpired contract. Source
consumption rows are not a product-specific charging calculation. No dollar
estimate, legal/compliance verdict, SKU/effective-date substitution, instance write,
Store install/update, or record export is performed.
